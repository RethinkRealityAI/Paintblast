## Corrections vs. the original spec and plan

These are the things the original spec/plan got wrong. Use the right-hand column.

| Spec/plan said | Reality |
|---|---|
| `features.enableGrabbing`, `features.enablePhysics`, `features.enableUIKitML` | `features.grabbing`, `features.physics`, `features.spatialUI`, `features.sceneUnderstanding`, `features.environmentRaycast`, `features.locomotion` |
| `Types.UInt8`, `Types.UInt16` | **These don't exist.** Use `Types.Int8`, `Types.Int16`, `Types.Int32`, `Types.Uint32`, `Types.Float32`, `Types.Float64`, `Types.Boolean`, `Types.String`, `Types.Vec3`, `Types.Vec4`, `Types.Color` (RGBA, 4 floats), `Types.Entity`, `Types.Enum`, `Types.Object` |
| Store separate `colorR`/`colorG`/`colorB` float fields | Use one `Types.Color` field (stores RGBA as 4 floats, more idiomatic) |
| `import * as THREE from 'three'` | **Forbidden.** `import { Vector3, Mesh, MeshStandardMaterial, SphereGeometry, CircleGeometry, InstancedMesh, Color, Quaternion, Matrix4, DoubleSide } from '@iwsdk/core';` IWSDK re-exports Three.js to avoid duplicate-instance bugs. Only GLTFLoader types come from `three/addons`. |
| Subscribe `queries.slots.subscribe('grab', ...)` | **Not a real event.** Add an `Interactable` component. When an entity is grabbed, the input system attaches a `Pressed` component. Query with `required: [Interactable, Pressed]` and subscribe to `'qualify'` and `'disqualify'` to detect press-start and press-end. |
| `world.physics.addStaticPlaneBody(entity)` | **No such method.** Physics is component-based: add `PhysicsBody` + `PhysicsShape` components to the entity and `PhysicsSystem` handles it. For static world geometry (walls, floors): `PhysicsState.Static`. |
| `world.ui.store` with reactive bindings | **No such object.** For cross-system reactive state, use `world.globals` + `@preact/signals-core`'s `signal()`. UI reads state by querying `PanelUI` entities and calling `PanelDocument.data.document[entity.index].getElementById('id').setProperties({ text: '…' })`. |
| `userData.xrDepthOcclusion = true` on materials | **Wrong mechanism.** Add the built-in `DepthOccludable` component to the entity. `DepthSensingSystem` handles the rest when `xr.features.depthSensing: true` is set. |
| UIKitML XML-component syntax (`<root>`, `<container bind:each="…">`) | **Wrong syntax.** UIKitML is HTML/CSS-like: `<style>` block + `<div class="…">`, `<span>`, `<button id="…">`. See Welcome template for the real shape. Compiled at build time by `@iwsdk/vite-plugin-uikitml` from `ui/*.uikitml` → `public/ui/*.json`. The `PanelUI` component's `config` field references the compiled `.json` path. |
| `src/ui/*.uikitml` | **Wrong path.** UIKitML files live in `ui/` at project root (not `src/ui/`). Compiled output lands in `public/ui/`. |
| Barrel exports: `src/components/index.ts`, `src/systems/index.ts` | **Against convention.** CLAUDE.md says "One system per file, with its related components. No barrel `index.ts` files." Put each system and its related component(s) in one file. Import by direct path. |
| Separate `createComponent` files per component with test files in `tests/unit/components/<name>.test.ts` | Keep the one-file-per-system convention: `src/systems/BallSpawnSystem.ts` defines `Ball` component AND `BallSpawnSystem` class. Tests match that: `tests/unit/systems/BallSpawnSystem.test.ts`. |
| Vitest `test:watch`, `test:ui` — use `src/**/*.ts` glob | Respected; still the plan. But note `tsconfig.json` only includes `src/**/*.ts`, so type-check will ignore `tests/`. Add `tests/**/*.ts` to `tsconfig.include` if we want TS type-check over tests. |
| Port `5173` | **Wrong.** Vite dev server runs on **`8081`** per `vite.config.ts`. |

## Confirmed API surface

### World.create

```typescript
import { World, SessionMode } from '@iwsdk/core';

const world = await World.create(container, {
  render: {
    fov: 50,
    near: 0.1,
    far: 200,
    defaultLighting: true,
  },
  assets: {
    /* AssetManifest entries if needed */
  },
  xr: {
    sessionMode: SessionMode.ImmersiveAR,
    offer: 'always',
    features: {
      handTracking: true,
      anchors: true,
      hitTest: true,
      planeDetection: true,
      meshDetection: true,
      depthSensing: true,
      layers: true,
    },
  },
  features: {
    locomotion: false,
    grabbing: true,
    physics: true,
    sceneUnderstanding: true,
    environmentRaycast: true,
    spatialUI: { forwardHtmlEvents: true, preferredColorScheme: 'dark' },
  },
});
```

`World.create()` returns a Promise. After it resolves, the world exposes:

- `world.camera` (PerspectiveCamera)
- `world.scene` (Scene)
- `world.renderer` (WebGLRenderer)
- `world.player` (XROrigin Group — `.head`, `.raySpaces.{left,right}`, `.gripSpaces.{left,right}`)
- `world.input` (XRInputManager — `.gamepads.{left,right}`)
- `world.visibilityState` (Signal<VisibilityState>)
- `world.globals` (Record<string, any>) — store cross-system signals here
- `world.activeLevel` (Signal<Entity>) — current level root entity
- `world.launchXR()`, `world.exitXR()`
- `world.session?.updateTargetFrameRate(72)`
- `world.registerComponent(C)`, `world.registerSystem(S, { priority? })` — both chainable
- `world.createTransformEntity(object3D, { parent?: Entity, persistent?: boolean }): Entity`
- `world.createEntity(): Entity`
- `world.getSystem(SystemClass): System`
- `world.getActiveRoot()` / `world.getPersistentRoot()`

### createComponent

```typescript
import { createComponent, Types } from '@iwsdk/core';

// Tag component (no data)
export const Interactable = createComponent('Interactable', {}, '');

// Data component
export const Ball = createComponent('Ball', {
  kind:        { type: Types.Int8,    default: 0 },
  color:       { type: Types.Color,   default: [1, 1, 1, 1] }, // RGBA
  radius:      { type: Types.Float32, default: 0.04 },
  spawnTime:   { type: Types.Float64, default: 0 },
  bounceCount: { type: Types.Int8,    default: 0 },
});

// With enums
export const BallKind = createComponent('BallKind', {
  mode: {
    type: Types.Enum,
    enum: { Normal: 'normal', Bouncy: 'bouncy', Sticky: 'sticky', Splash: 'splash' },
    default: 'normal',
  },
});
```

Component data access:

```typescript
entity.addComponent(Ball, { kind: 1, color: [1, 0.5, 0, 1], radius: 0.04 });
entity.getValue(Ball, 'radius'); // 0.04
entity.setValue(Ball, 'radius', 0.05);
entity.getVectorView(Transform, 'position'); // Float32Array — zero-alloc
entity.hasComponent(Ball);
entity.removeComponent(Ball);
entity.destroy();  // removes components, detaches Object3D
entity.dispose();  // destroy() + GPU resource cleanup
```

### createSystem

```typescript
import { createSystem, Types } from '@iwsdk/core';

export class MySystem extends createSystem(
  // Queries (required, excluded, where filters)
  {
    balls: { required: [Ball] },
    liveBalls: { required: [Ball], excluded: [Dead] },
    lowHealth: { required: [Health], where: [lt(Health, 'current', 20)] },
  },
  // Config (becomes reactive signals)
  {
    speed: { type: Types.Float32, default: 5.0 },
  },
) {
  private temp!: Vector3;

  init() {
    this.temp = new Vector3(); // allocate in init, not update

    this.queries.balls.subscribe('qualify', (entity) => {
      // Entity entered the query (e.g. component added)
    });
    this.queries.balls.subscribe('disqualify', (entity) => {
      // Entity left the query (component removed or entity destroyed)
    });

    // Register cleanup for subscriptions so they're torn down on level change
    this.cleanupFuncs.push(
      this.config.speed.subscribe((v) => console.log('speed:', v))
    );
  }

  update(delta: number, time: number) {
    const speed = this.config.speed.peek(); // use peek(), NOT .value, in hot loops
    for (const entity of this.queries.liveBalls.entities) {
      // do work. NO allocations.
    }
  }
}
```

System-side access helpers: `this.world`, `this.queries`, `this.config`, `this.player`, `this.input`, `this.scene`, `this.camera`, `this.renderer`, `this.visibilityState`, `this.globals`, `this.createEntity()`, `this.createTransformEntity(obj, parent?)`, `this.cleanupFuncs`.

### Grab detection pattern

The grabbing system attaches a `Pressed` component to Interactable entities while they are being pressed/squeezed. To detect a grab:

```typescript
import { createSystem, Interactable, Pressed, OneHandGrabbable } from '@iwsdk/core';

export class PaletteGrabSystem extends createSystem({
  grabbedSlots: { required: [PaletteSlot, Interactable, Pressed] },
}) {
  init() {
    this.queries.grabbedSlots.subscribe('qualify', (entity) => {
      // Just got pressed — spawn a ball in the grabbing hand
    });
    this.queries.grabbedSlots.subscribe('disqualify', (entity) => {
      // Released
    });
  }
}
```

To make something draggable by hand, add **both** `Interactable` and a grabbable component:

```typescript
entity.addComponent(Interactable);
entity.addComponent(OneHandGrabbable, { rotate: false, translate: true });
```

### Physics pattern

Physics is entirely component-based. For a ball:

```typescript
import { PhysicsBody, PhysicsShape, PhysicsState, PhysicsShapeType } from '@iwsdk/core';

entity.addComponent(PhysicsBody, {
  state: PhysicsState.Dynamic,
  linearDamping: 0.02,
  angularDamping: 0.05,
  gravityFactor: 1.0,
});
entity.addComponent(PhysicsShape, {
  shape: PhysicsShapeType.Sphere,
  dimensions: [0.04, 0, 0], // [radius, 0, 0] for Sphere
  density: 10,
  restitution: 0.2, // bounciness (0-1)
  friction: 0.3,
});
```

For static walls/floors (derived from XRPlane entities):

```typescript
entity.addComponent(PhysicsBody, { state: PhysicsState.Static });
entity.addComponent(PhysicsShape, {
  shape: PhysicsShapeType.Auto, // infer from object3D geometry
  restitution: 0.1,
  friction: 0.8,
});
```

Apply forces / set velocity via one-shot `PhysicsManipulation`:

```typescript
import { PhysicsManipulation } from '@iwsdk/core';

entity.addComponent(PhysicsManipulation, {
  force: [0, 10, 0],
  linearVelocity: [2, 0, -5],
  angularVelocity: [0, 0, 0],
});
// PhysicsSystem applies and auto-removes the component
```

### Depth occlusion (AR)

```typescript
import { DepthOccludable } from '@iwsdk/core';

entity.addComponent(DepthOccludable);
```

Prerequisites: `xr.features.depthSensing: true` in World.create. `DepthSensingSystem` handles the rendering. Feature-detect at runtime by checking whether the component takes effect (no explicit API needed; the system silently no-ops if depth isn't available).

### Scene understanding

```typescript
import { XRPlane, XRMesh, XRAnchor } from '@iwsdk/core';

export class WorldCollisionSystem extends createSystem({
  planes: { required: [XRPlane] },
  meshes: { required: [XRMesh] },
}) {
  init() {
    this.queries.planes.subscribe('qualify', (entity) => {
      // entity.object3D is the plane mesh
      entity.addComponent(PhysicsBody, { state: PhysicsState.Static });
      entity.addComponent(PhysicsShape, {
        shape: PhysicsShapeType.Auto,
        restitution: 0.1,
        friction: 0.8,
      });
    });

    this.queries.planes.subscribe('disqualify', (entity) => {
      entity.removeComponent(PhysicsBody);
      entity.removeComponent(PhysicsShape);
    });

    this.queries.meshes.subscribe('qualify', (entity) => {
      const label = entity.getValue(XRMesh, 'semanticLabel');
      if (label && ['table', 'couch', 'chair', 'other'].includes(label as string)) {
        entity.addComponent(PhysicsBody, { state: PhysicsState.Static });
        entity.addComponent(PhysicsShape, {
          shape: PhysicsShapeType.Auto,
          restitution: 0.2,
          friction: 0.7,
        });
      }
    });
  }
}
```

Prerequisites: `features.sceneUnderstanding: true`, `xr.features: { planeDetection: true, meshDetection: true, anchors: true }`, `SessionMode.ImmersiveAR`.

### UIKitML

Files live in `ui/*.uikitml`. Compile at build time (via `@iwsdk/vite-plugin-uikitml`) to `public/ui/*.json`. Format is HTML/CSS-like:

```xml

<style>

    display: flex;
    flex-direction: column;
    padding: 2;
    background-color: #09090b;
    border-radius: 3;
    border-width: 0.15;
    border-color: #27272a;
    width: 40;
  }
  .palette-title {
    font-size: 3;
    color: #fafafa;
    margin-bottom: 1;
  }
  .palette-row {
    display: flex;
    flex-direction: row;
    gap: 1;
  }
  .palette-slot {
    width: 6;
    height: 6;
    border-radius: 1;
    border-width: 0.1;
    border-color: #3f3f46;
  }
</style>
<div class="palette-root">
  <span class="palette-title">Palette</span>
  <div class="palette-row">
    <div id="slot-0" class="palette-slot" style="background-color: #ff6b6b"></div>
    <div id="slot-1" class="palette-slot" style="background-color: #feca57"></div>

    <div id="slot-3" class="palette-slot" style="background-color: #4ecb85"></div>
  </div>
  <!-- ... rows for the other 12 slots ... -->

```

Mount it with the `PanelUI` component, referencing the **compiled** `.json` path:

```typescript
import { PanelUI, PanelDocument, ScreenSpace, Interactable } from '@iwsdk/core';

const panelEntity = world
  .createTransformEntity()
  .addComponent(PanelUI, {
    config: './ui/palette.json', // compiled output
    maxHeight: 0.4,
    maxWidth: 0.4,
  })
  .addComponent(Interactable);

panelEntity.object3D.position.set(-0.4, 1.0, -0.6);
```

Interact with the mounted UI from a system:

```typescript
import { createSystem, PanelUI, PanelDocument, UIKitDocument, UIKit, eq } from '@iwsdk/core';

export class PaletteUISystem extends createSystem({
  panel: {
    required: [PanelUI, PanelDocument],
    where: [eq(PanelUI, 'config', './ui/palette.json')],
  },
}) {
  init() {
    this.queries.panel.subscribe('qualify', (entity) => {
      const doc = PanelDocument.data.document[entity.index] as UIKitDocument;
      if (!doc) return;
      for (let i = 0; i < 16; i++) {
        const slot = doc.getElementById(`slot-${i}`) as UIKit.Container | null;
        if (!slot) continue;
        slot.addEventListener('click', () => {
          // dispatch paint spawn intent
        });
      }
    });
  }
}
```

## Project convention reminders (from CLAUDE.md)

- **One system per file**, paired with its related component(s). No barrel `index.ts`.
- **No allocations in `update()`** — allocate in `init()` as class properties.
- **No `.value` in update loops** — use `.peek()`.
- **Track subscriptions** — `this.cleanupFuncs.push(signal.subscribe(...))`.
- **`entity.dispose()`** for entities with GPU resources; `entity.destroy()` only when resources are shared.
- **Scene objects via `createTransformEntity`**, never `scene.add()`.
- **Assets via `AssetManager`**, never raw `GLTFLoader`.
- **`ScreenSpace` values are CSS strings** — `'400px'`, not `400`.
- **Type-check BEFORE running** — `npx tsc --noEmit` after every meaningful change. TS errors don't always surface in the browser console.

Because the scaffold does more than the plan expected:

- **Task 10 (UIKitML palette + HUD markup)** uses the HTML/CSS-like syntax, not the plan's XML syntax.

The plan's overall task sequence and TDD structure still apply. Subagents should treat the plan's code blocks as "intent," and this file as "reality." When they conflict, reality wins.
